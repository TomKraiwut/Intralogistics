5.2 สอบภาคปฏิบัติ

5. การวัดและประเมินผล · ภาคปฏิบัติ

วัตถุประสงค์การเรียนรู้

  1. สร้างแบบจำลองคลังรับสินค้าจากโจทย์ได้ด้วยตัวเอง
  2. เขียน Method วัดผล และใช้ ExperimentManager หาจำนวน Forklift ที่พอดีได้
  3. อธิบายผลด้วยกำลังการทำงานต่อชั่วโมงได้ และสอบผ่านไม่น้อยกว่าร้อยละ 60

สร้างแบบจำลองท่ารับสินค้าใหม่เองตั้งแต่เฟรมเปล่า แล้วหาว่าต้องใช้ Forklift กี่คัน — ใช้ทักษะจากบท 1.3, 1.4 และ 3.2 · คะแนนเต็ม 100 ผ่าน 60 คะแนนขึ้นไป

สิ่งที่ต้องมี: Plant Simulation (โมเดลใหม่ ไม่ต้องใช้ไฟล์ตัวอย่าง) · ดูบทเรียนบนเว็บได้ · อย่าปิดโปรแกรมหลังส่งคำตอบ ผู้สอนจะตรวจแบบจำลองบนหน้าจอของคุณ

โจทย์

ท่ารับสินค้ามีรถส่งพาเลทเข้ามาสม่ำเสมอทุก 2 นาที พาเลทพักที่ท่ารับได้ไม่เกิน 100 พาเลท Forklift แต่ละคันยกพาเลทขึ้นชั้นคันละ 5 นาทีต่อพาเลท ทำงาน 1 กะ 8 ชั่วโมง

ส่วนที่ 1: สร้างแบบจำลอง

Objectชื่อตั้งค่า
SourceInboundInterval 2:00
BufferDockCapacity 100 · Processing time 0
ParallelStationPutawayProcessing time 5:00 · X-Dimension = จำนวน Forklift · Y-Dimension 1 · ☐ Start Processing When Full
DrainRack—
EventControllerEnd 8:00:00

ต่อ Connector: Inbound → Dock → Putaway → Rack

ส่วนที่ 2: Method วัดผล

สร้าง Method LeadTimeMin คืนค่าเวลาเฉลี่ยตั้งแต่พาเลทมาถึงจนขึ้นชั้น เป็นนาที (จาก Rack.StatAvgLifeSpan) — ถ้ายังไม่มีพาเลทเข้า Rack ให้คืน 0 (ดูตัวอย่างในบท 3.2 ขั้นที่ 5)

ส่วนที่ 3: ทดลองและตอบคำถาม

  1. 1ตั้ง Forklift 2 คัน รัน 8 ชั่วโมง → ข้อ 1 พาเลทที่ขึ้นชั้น (Rack) · ข้อ 2 พาเลทที่ค้างที่ Dock ตอนจบ
  2. 2สร้าง ExperimentManager: Input root.Putaway.XDim = 1, 2, 3, 4, 5 · Output root.Rack.StatNumIn, root.Dock.NumMU, root.LeadTimeMin → Reset › Start
  3. 3ข้อ 3 จำนวน Forklift น้อยที่สุดที่ไม่มีพาเลทค้างที่ Dock
  4. 4ข้อ 4 เวลาเฉลี่ย (นาที) ของจำนวน Forklift ในข้อ 3
  5. 5ข้อ 5 อธิบายว่าทำไมจำนวนในข้อ 3 พอ แต่น้อยกว่านั้นไม่พอ — คิดเป็นพาเลทต่อชั่วโมง
ตรวจก่อนส่ง: ถ้าลืมเอาเครื่องหมายออกจาก Start Processing When Full Forklift จะรอจนทุกช่องมีพาเลทก่อนเริ่มงาน และตัวเลขทุกข้อจะผิด
